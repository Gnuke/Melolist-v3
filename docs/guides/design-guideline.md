# Melolist 디자인 적용 가이드

## 핵심 방향
Melolist는 음악 스트리밍 앱이 아니다.
Spotify, Apple Music 같은 “음악을 듣는 앱” UI를 그대로 따라하지 않는다.

Melolist의 핵심 경험은 다음 순서다.

1. 사용자가 기억나는 노래를 검색한다.
2. 허밍/키워드/가사 단서로 후보곡을 찾는다.
3. 후보곡을 확인한다.
4. 찾은 곡을 저장하거나 리뷰한다.

## 디자인 목표
- 음악 감상 앱이 아니라 “음악 발견/검색/기록 앱”처럼 보이게 한다.
- 플레이어 UI를 메인으로 두지 않는다.
- 앨범 커버, 재생 버튼, 플레이리스트 중심 구조를 과하게 사용하지 않는다.
- 검색, 인식 결과, 후보 비교, 리뷰 작성 흐름을 중심으로 화면을 설계한다.

## 참고 디자인 사용 방식
참조 이미지는 색감, 카드 스타일, 여백, 타이포그래피, 그라데이션, 인터랙션 분위기만 참고한다.
화면 구조를 그대로 복제하지 않는다.

## 피해야 할 것
- 하단 미니 플레이어 고정
- 대형 앨범 커버 중심 홈
- 재생/일시정지 버튼 중심 UI
- 플레이리스트 피드 중심 화면
- “지금 듣기”, “추천 플레이리스트” 중심 문구

## 적용해야 할 것
- 메인 CTA: “노래 찾기”, “허밍으로 찾기”, “기록 보기”
- 검색 입력창을 가장 중요한 UI로 배치
- 인식 결과는 카드 형태로 표시
- 후보곡은 confidence, artist, title, source 기준으로 비교 가능하게 표시
- 리뷰/평가 기능은 곡을 찾은 다음의 후속 행동으로 배치

## 화면 우선순위
1. Home
   - 검색/허밍 시작 중심
   - 최근 찾은 곡
   - 최근 리뷰

2. Search Result
   - 후보곡 리스트
   - 정확도 또는 매칭 신뢰도
   - YouTube 확인 버튼
   - 저장/리뷰 작성 버튼

3. Review
   - 곡 정보
   - 별점/텍스트 리뷰
   - 내 기록으로 저장

4. My Library
   - 내가 찾은 곡
   - 내가 작성한 리뷰
   - 검색 이력

## 톤
- 감성적이되 과하게 스트리밍 서비스처럼 보이지 않게 한다.
- “듣기”보다 “찾기/확인/기록”이 중심이다.
- 음악 앱의 분위기는 가져오되, 기능 구조는 검색 서비스에 가깝게 만든다.
