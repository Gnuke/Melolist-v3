## 확정 OKR

> **Objective**: 처음 방문한 게스트가 30초 안에 흥얼거린 곡을 찾아내는, 신뢰할 수 있는 검색 경험을 완성한다.

| # | Key Result | 목표치 | 측정 방법 |
|---|---|---|---|
| KR1 | 검색 매칭률 (내부 테스트 곡 셋) | 지문 ≥ 80% · 허밍 ≥ 50% | 테스트 곡 셋(지문 30곡 + 허밍 20곡)을 측정 스크립트로 `/api/search/*`에 반복 투입, Top-3 내 정답 포함률 |
| KR2 | 검색 응답 시간 | p95 ≤ 6초 (녹음 종료→결과 표시) | 서버: 요청 수신→응답 완료 타이밍 로그. 클라: 종료 버튼→렌더 완료 계측(개발 빌드) |
| KR3 | 첫 방문 내 검색 완료율 (베타) | ≥ 70% | 이벤트 로그: `visit` 대비 `search_result_shown` 세션 비율. **베타 코호트 10~20명 전제** |

### KR별 실행 메모

**KR1 — 매칭률**
- 테스트 곡 셋 구성 기준: 장르 분산(K-pop/팝/OST/힙합/클래식), 발매연도 분산, 허밍은 남/녀·원키/이조 섞기
- 정답 판정: ACRCloud 응답의 acrid/제목-아티스트가 기대값과 일치하면 성공. Top-1이 아닌 **Top-3 기준**(결과 리스트 UX 전제)
- 측정 스크립트는 `backend/scripts/match-rate/`에 있고 CI와 무관하게 수동 실행 (분기 중 3회 이상: M2 중간·M2 완료·분기 말)

**KR2 — 응답 시간**
- 병목 예상 지점: 오디오 업로드 크기(webm 인코딩), ACRCloud 왕복, MUSIC upsert. 구간별 타이밍 로그로 분해 측정
- p95 산출 모수: 테스트 곡 셋 실행 로그 + 베타 실사용 로그 합산 — 산출 SQL은 `backend/db/queries/kr_metrics.sql`

**KR3 — 검색 완료율**
- 필요 이벤트: `visit` · `search_started` · `search_result_shown` · `search_failed` — M2에서 구현 완료(`event_log`)
- 베타 모집이 분기 내 불발되면 KR3은 미측정 처리하고 KR1·KR2로 분기 평가 (KR3 목표를 낮추지 않음)

### 헬스 메트릭 (관찰만, 목표 없음)

- 검색→저장 전환율·리뷰 작성률·재방문율(D7/D30): 해당 기능이 생기는 시점부터 이벤트 원천만 수집
- 빌드/배포 상태: CI 통과율
