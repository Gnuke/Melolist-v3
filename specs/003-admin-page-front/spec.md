## User Scenarios & Testing *(mandatory)*

### User Story 1 - 운영 지표 대시보드 (Priority: P1)

관리자가 어드민 화면에 접속해 Q3 OKR의 KR 지표 — 검색 응답 시간(KR2 p95 ≤ 6초)과
첫 방문 검색 완료율(KR3 ≥ 70%) — 를 목표 달성 여부와 함께 한눈에 확인한다. 검색량·
매칭 현황, 실패 사유 분포, 주간 추이까지 화면에서 조회하며, 조회 기간(기본 최근 14일)을
바꿔 볼 수 있다.

**Why this priority**: 현재 KR 지표 산출은 관리자가 SQL 파일을 데이터베이스 콘솔에
수동으로 붙여넣어 실행하는 방식이다(backend-prd §10). 지표 확인의 마찰이 크면 측정
주기가 늘어져 "측정 가능성 기본 탑재"(constitution 원칙 III)의 실효가 떨어진다.
어드민의 최우선 존재 이유가 이 마찰 제거다.

**Independent Test**: 관리자 계정으로 어드민 대시보드에 진입해 KR2·KR3 수치와 목표
대비 상태가 표시되는 것을 확인하고, 기간을 변경해 수치가 갱신되는 것을 확인하는 것만으로
독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 관리자 권한 계정으로 로그인했다, **When** 어드민 대시보드에 진입한다,
   **Then** 최근 14일 기준 KR2 p95(모드별·전체)와 KR3 완료율이 각 목표(6초·70%) 대비
   달성 여부와 함께 표시된다.
2. **Given** 대시보드가 표시돼 있다, **When** 조회 기간을 변경한다, **Then** 모든
   지표가 해당 기간 기준으로 갱신된다.
3. **Given** KR2가 목표 미달이다, **When** 상세를 확인한다, **Then** 처리 구간별
   (인식·메타 보강 등) 분해 수치로 병목 구간을 식별할 수 있다.
4. **Given** 기간 내 검색 실패가 존재한다, **When** 실패 현황을 확인한다, **Then**
   실패 사유별 분포(무결과·저신뢰·오류·시간 초과·취소 등)를 확인할 수 있다.
5. **Given** 일반 사용자 또는 게스트다, **When** 어드민 주소로 직접 접근한다,
   **Then** 어드민 화면은 표시되지 않고 접근이 차단된다.

### User Story 2 - 곡 카탈로그 점검·보정 (Priority: P2)

관리자가 서비스에 캐시된 곡 목록을 조회·검색하고, 메타데이터가 누락된 곡(재생 링크
없음·커버 이미지 없음)을 필터로 찾아내 곡 정보(제목·아티스트·앨범·재생 영상 식별자·
커버 이미지 링크)를 수정한다.

**Why this priority**: 곡 데이터는 인식 결과를 캐시한 것이라 재생 링크·커버가 비어
있을 수 있고, 마스터 PRD 부록 A.1은 "링크는 추후 재해석 가능"을 전제로 저장을 허용했다.
현재 그 재해석 수단이 없다 — 잘못되거나 빈 메타데이터를 고칠 방법은 데이터베이스 직접
수정뿐이다. 곡 카드의 듣기 버튼·커버는 핵심 경험이므로 보정 수단의 가치가 크다.

**Independent Test**: 어드민에서 곡 목록을 열어 "재생 링크 없음" 필터로 곡을 찾고,
재생 영상 식별자를 입력·저장한 뒤 해당 곡 정보가 갱신되는 것을 확인하는 것만으로
독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 어드민에 진입한 관리자다, **When** 곡 카탈로그 화면을 연다, **Then**
   곡 목록이 페이지 단위로 표시되고 제목·아티스트로 검색할 수 있다.
2. **Given** 곡 목록이 표시돼 있다, **When** "재생 링크 없음" 또는 "커버 없음" 필터를
   적용한다, **Then** 해당 메타데이터가 비어 있는 곡만 표시된다.
3. **Given** 곡 하나를 선택했다, **When** 곡 정보를 수정하고 저장한다, **Then** 변경
   내용이 반영되고 확인 피드백이 표시된다.
4. **Given** 곡 정보를 수정 중이다, **When** 형식이 잘못된 값(유효하지 않은 영상
   식별자·링크 형식)을 저장하려 한다, **Then** 저장이 거부되고 이유가 안내된다.

### User Story 3 - 사용자·권한 관리 (Priority: P3)

관리자가 가입 사용자 목록(별명·이메일·가입일·역할)을 조회하고, 특정 사용자에게 관리자
역할을 부여하거나 해제한다.

**Why this priority**: 관리자 역할 지정은 현재 데이터베이스 직접 수정으로만 가능하다.
1인 운영 단계에서는 빈도가 낮아 P3이지만, 어드민 접근 제어(US1)의 관리 수단으로서
장기적으로 필요하다.

**Independent Test**: 사용자 목록에서 일반 사용자 한 명에게 관리자 역할을 부여하고,
그 계정으로 어드민 접근이 가능해지는 것(및 해제 시 다시 차단되는 것)을 확인하는 것만으로
독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 어드민에 진입한 관리자다, **When** 사용자 관리 화면을 연다, **Then**
   사용자 목록이 별명·이메일·가입일·역할과 함께 페이지 단위로 표시된다.
2. **Given** 일반 사용자 한 명을 선택했다, **When** 관리자 역할을 부여한다, **Then**
   해당 사용자의 역할이 갱신되고 그 계정으로 어드민 접근이 가능해진다.
3. **Given** 관리자 자신의 계정이다, **When** 자신의 관리자 역할을 해제하려 한다,
   **Then** 실수로 인한 접근 상실을 막기 위해 해제가 거부된다.

---

### Edge Cases

- 조회 기간에 데이터가 전혀 없으면(방문 0건 등 분모 0)? → 오류가 아닌 "데이터 없음"
  상태로 표시한다.
- 지표·목록 로딩 중이거나 서버가 콜드스타트로 느리면? → 로딩 상태를 표시하고, 실패 시
  정제된 안내와 재시도 수단을 제공한다. 원문 오류 메시지는 노출하지 않는다(기존 실패
  UX 규칙 계승).
- 비관리자가 어드민 주소를 직접 입력하면? → 어드민 화면·데이터를 일절 노출하지 않고
  차단한다(로그인 화면 또는 홈으로 안내).
- 어드민 이용 중 권한이 해제되면? → 이후의 조회·수정 요청은 거부되고 접근 차단 상태로
  전환된다.
- 곡 수정과 동시에 다른 경로(검색 파이프라인의 캐시 갱신)로 같은 곡이 갱신되면? →
  마지막 저장이 반영되되, 화면에는 저장 후 최신 상태를 다시 보여준다.
- 모바일에서 어드민에 접근하면? → 열람은 가능해야 하나(반응형), 어드민은 데스크톱
  우선으로 설계한다(기존 앱의 모바일 우선 원칙의 의도적 예외).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 관리자 역할을 가진 로그인 사용자만 어드민 화면에 접근할 수 있어야 한다.
  게스트·일반 사용자의 접근은 화면·데이터 노출 없이 차단되어야 한다.
- **FR-002**: 어드민은 기존 사용자 화면과 분리된 별도 영역으로 제공되어야 하며, 앱 내
  어떤 화면·내비게이션에도 어드민 진입점을 노출하지 않는다(관리자 포함 — 진입은 주소
  직접 접근만, 기존 사용자 경험 무변경).
- **FR-003**: 대시보드는 KR2(검색 응답 시간 p95 — 모드별·전체)와 KR3(첫 방문 검색
  완료율)를 각 목표값(6초·70%) 대비 달성 여부와 함께 표시해야 한다. 산출 정의는 기존
  KR 산출 SQL(backend-prd §10)의 정의를 정본으로 따른다.
- **FR-004**: 대시보드는 조회 기간을 조정할 수 있어야 하며(기본 최근 14일), 구간별
  분해(병목 식별), 실패 사유 분포, 주간 추이를 함께 제공해야 한다.
- **FR-005**: 대시보드는 서비스 현황 요약(기간 내 검색 수·매칭 수, 누적 가입자 수·
  곡 캐시 수)을 표시해야 한다.
- **FR-006**: 관리자는 곡 카탈로그를 목록 조회·텍스트 검색할 수 있어야 하며, 메타데이터
  누락(재생 링크 없음·커버 없음) 필터를 사용할 수 있어야 한다.
- **FR-007**: 관리자는 곡 정보(제목·아티스트·앨범·재생 영상 식별자·커버 이미지 링크)를
  수정할 수 있어야 한다. 커버는 외부 링크 문자열만 허용하며 이미지 업로드·재호스팅
  수단을 제공하지 않아야 한다(constitution 원칙 IV — 저작권 가드레일).
- **FR-008**: 관리자는 사용자 목록(별명·이메일·가입일·역할)을 조회하고 관리자 역할을
  부여·해제할 수 있어야 한다. 자기 자신의 관리자 역할 해제는 거부되어야 한다.
- **FR-009**: 어드민 화면 전체는 백엔드 없이 시뮬레이션 데이터만으로 동작·시연 가능해야
  한다(constitution 원칙 VI — 외부 의존 없는 테스트 가능성). 이는 백엔드가 별도 작업
  트리에서 병렬 구현되는 동안 프론트를 독립적으로 완성·검증하기 위한 필수 조건이다.
- **FR-010**: 어드민의 모든 오류 표시는 정제된 안내 문구를 사용해야 하며 시스템 원문
  오류 메시지를 노출하지 않아야 한다(기존 F4 규칙 계승).
- **FR-011**: 어드민은 개별 사용자의 사적 데이터(검색 기록 내용, 즐겨찾기·플레이리스트
  내용)를 열람하는 기능을 제공하지 않아야 한다. 지표는 집계 수치로만 표시한다
  (constitution 원칙 IV — 프라이버시 가드레일의 확장 적용).
- **FR-012**: 어드민 화면 이용은 서비스 지표를 오염시키지 않아야 한다 — 어드민 영역에서는
  방문·검색 등 사용자 행동 계측 이벤트를 발화하지 않는다(KR3 분모 오염 방지 — 기존
  운영에서 개발 세션 오염이 실제 관측된 바 있음).

### Key Entities

- **운영 지표**: 이벤트 기록에서 집계되는 파생 수치 — KR2(응답 시간 백분위, 구간별
  분해), KR3(세션 단위 완료율), 실패 분포, 주간 추이, 현황 요약. 어드민에서는 읽기 전용.
- **곡(카탈로그 항목)**: 인식 결과로 캐시된 곡. 제목·아티스트·앨범·발매일·재생 영상
  식별자·커버 이미지 링크를 가지며, 어드민에서 수정 가능한 유일한 쓰기 대상 중 하나.
- **사용자 프로필**: 서비스 이용 주체. 별명·이메일·가입일과 **역할**(일반/관리자)을
  가진다. 역할이 어드민 접근 제어의 기준이다(기존 프로필 체계의 역할 값 재사용).
- **조회 기간**: 대시보드 지표의 공통 매개변수(기본 최근 14일).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자가 어드민 진입부터 KR2·KR3 목표 달성 여부 확인까지 1분 이내에
  도달한다(현행 SQL 수동 실행 대비 도구 전환 0회).
- **SC-002**: 비관리자(게스트·일반 사용자)의 어드민 접근 시도가 100% 차단된다
  (화면·데이터 노출 0건).
- **SC-003**: 메타데이터 누락 곡을 필터로 찾아 수정 완료까지 2분 이내에 수행할 수 있다.
- **SC-004**: 백엔드가 기동되지 않은 상태에서 어드민 전 화면이 시뮬레이션 데이터로
  시연 가능하다(화면 커버리지 100%).
- **SC-005**: 기존 사용자 화면의 동작·계측에 회귀가 없다(기존 화면 변경 0건, 이벤트
  발화 변화 0건).
- **SC-006**: 어드민 이용 세션이 서비스 지표(방문·완료율)에 집계되지 않는다(오염 0건).

## Assumptions

- **관리자 지정(부트스트랩)**: 최초 관리자는 운영자가 데이터 저장소에서 직접 역할 값을
  지정한다(1인 운영 — 별도 관리자 가입 절차 없음). 기존 프로필 체계에 역할 값(기본
  일반 사용자)이 이미 존재하므로 이를 재사용하며, 새 데이터 구조 신설은 가정하지 않는다.
