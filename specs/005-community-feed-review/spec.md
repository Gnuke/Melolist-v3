- Q: 댓글 기능 범위는? → A: 단일 깊이(대댓글 없음)·수정 없이 작성자 본인 삭제만 —
  v1 확정. 대댓글·수정은 이후 마일스톤에서 필요 시 재검토.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 커뮤니티 탐색: 공개 플레이리스트 피드 (Priority: P1)

처음 방문한 게스트를 포함해 누구나 커뮤니티 화면에 들어가 **다른 사용자들이 공개한
플레이리스트**를 둘러볼 수 있다. 피드에는 플레이리스트의 이름·곡 수·대표 커버·만든
사람의 닉네임이 보이고, 항목을 선택하면 기존의 공개 플레이리스트 상세 화면으로 이동해
담긴 곡을 확인하고 재생할 수 있다. 서비스가 "나만의 검색 도구"에서 "다른 사람의 발견을
구경하는 공간"으로 확장되는 첫 단추다.

**Why this priority**: 이미 존재하는 공개 플레이리스트 데이터만으로 즉시 가치를
전달할 수 있는 유일한 스토리다(신규 콘텐츠 작성 없이 동작). 게스트 우선 원칙(핵심
조회는 비로그인 즉시 사용)에 부합하고, 검색→저장→공유로 이어지는 리텐션 루프의 "공유"
구간을 처음으로 연다.

**Independent Test**: 공개 플레이리스트가 1개 이상 있는 상태에서 게스트로 커뮤니티
화면 진입 → 피드 표시 → 항목 선택 → 기존 공개 상세로 이동까지 로그인 없이 확인
가능하다. 이 흐름만으로 독립 배포·시연이 가능하다.

**Acceptance Scenarios**:

1. **Given** 공개 플레이리스트가 1개 이상 존재한다, **When** 게스트가 커뮤니티
   화면에 진입한다, **Then** 공개 플레이리스트 피드가 최신순으로 표시되고 각 항목에
   이름·곡 수·대표 커버·작성자 닉네임이 보인다.
2. **Given** 피드가 표시되어 있다, **When** 항목 하나를 선택한다, **Then** 해당
   플레이리스트의 공개 상세 화면으로 이동해 담긴 곡을 조회할 수 있다.
3. **Given** 공개 플레이리스트가 하나도 없다, **When** 커뮤니티 화면에 진입한다,
   **Then** 비어 있음을 알리는 안내와 함께 화면이 깨지지 않고 표시된다.
4. **Given** 피드에 노출된 플레이리스트가 이후 비공개로 전환되었다, **When** 사용자가
   해당 항목의 상세로 진입을 시도한다, **Then** 내용은 노출되지 않고 접근 불가 안내가
   표시된다(존재 비노출).
5. **Given** 피드 첫 페이지를 보고 있다, **When** 목록 끝까지 스크롤한다, **Then**
   다음 페이지가 이어서 로드된다.

### User Story 2 - 서비스 리뷰 작성·수정·삭제와 리뷰 피드 (Priority: P2)

로그인 사용자는 **서비스 전반에 대한 평가**(별점 1~5 + 텍스트)를 남길 수 있다. 리뷰는
곡에 대한 평가가 아니라 앱에 대한 평가이므로 **한 사람당 1건**만 존재한다. 이미 리뷰를
쓴 사용자가 다시 작성을 시도하면 중복임을 안내하고 기존 리뷰의 수정으로 유도한다.
작성된 리뷰는 커뮤니티 화면의 리뷰 피드에 별점·내용·닉네임·작성일과 함께 최신순으로
노출되며, 게스트도 조회할 수 있다. 수정·삭제는 작성자 본인만 가능하다.

**Why this priority**: v2에서 검증된 핵심 커뮤니티 기능의 승계이며, 헬스 메트릭
"리뷰 작성률"의 원천이다. 공개 플레이리스트 피드(US1)가 열린 뒤에 리뷰 피드가
더해져야 커뮤니티 화면이 완성된다.

**Independent Test**: 로그인 계정으로 리뷰 작성 → 피드 노출 확인 → 같은 계정으로
재작성 시도 시 중복 안내 → 수정·삭제 동작 확인. US1 없이도 리뷰 작성·조회만으로
독립 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 리뷰를 쓴 적 없는 로그인 사용자다, **When** 별점과 내용을 입력해
   제출한다, **Then** 리뷰가 저장되고 커뮤니티 리뷰 피드 최상단에 노출된다.
2. **Given** 이미 리뷰를 작성한 사용자다, **When** 새 리뷰 작성을 시도한다,
   **Then** 저장은 거부되고(1인 1리뷰) 이미 작성했음을 알리는 안내와 함께 기존
   리뷰를 수정하는 흐름으로 유도된다.
3. **Given** 내가 작성한 리뷰가 있다, **When** 별점 또는 내용을 수정하거나 삭제한다,
   **Then** 변경 사항이 피드에 반영되고, 삭제 시 피드에서 사라지며 이후 새 리뷰
   작성이 다시 가능해진다.
4. **Given** 게스트 상태다, **When** 리뷰 피드를 조회한다, **Then** 별점·내용·
   닉네임·작성일이 보인다. **When** 리뷰 작성을 시도한다, **Then** 로그인 유도가
   표시되고 로그인 완료 후 커뮤니티 리뷰 세그먼트로 복귀한다(작성 시트 자동 재오픈은
   요구하지 않음).
5. **Given** 다른 사용자의 리뷰다, **When** 수정·삭제를 시도한다, **Then** 권한
   없음으로 거부된다(본인 확인).

### User Story 3 - 공개 플레이리스트 댓글 (Priority: P3)

로그인 사용자는 공개 플레이리스트 상세 화면에서 **댓글**을 남길 수 있다. 댓글 목록은
게스트를 포함해 누구나 볼 수 있고, 삭제는 작성자 본인만 가능하다. 플레이리스트를 만든
사람과 구경하는 사람 사이에 첫 상호작용이 생긴다.

**Why this priority**: US1(피드)·US2(리뷰)가 갖춰진 뒤에 의미가 커지는
상호작용 기능. 단독으로도 공개 플레이리스트 상세에 붙여 독립 검증 가능하다.

**Independent Test**: 공개 플레이리스트 상세에서 로그인 계정으로 댓글 작성 → 목록
노출 → 게스트로 조회 확인 → 작성자 삭제 확인.

**Acceptance Scenarios**:

1. **Given** 공개 플레이리스트 상세를 보고 있는 로그인 사용자다, **When** 댓글을
   입력해 제출한다, **Then** 댓글이 목록에 추가되고 닉네임·내용·작성 시각이 표시된다.
2. **Given** 게스트 상태다, **When** 댓글 목록을 본다, **Then** 조회는 가능하다.
   **When** 댓글 작성을 시도한다, **Then** 로그인 유도가 표시되고 로그인 후 원래
   맥락으로 복귀한다.
3. **Given** 내가 작성한 댓글이 있다, **When** 삭제한다, **Then** 목록에서 사라진다.
   다른 사용자의 댓글에는 삭제 수단이 제공되지 않는다.
4. **Given** 댓글이 달린 플레이리스트가 비공개로 전환되거나 삭제되었다, **When**
   댓글 작성을 시도한다, **Then** 저장은 거부되고 대상이 더 이상 공개 상태가 아님을
   안내한다.

### User Story 4 - 리뷰 작성 유도 (Priority: P4)

검색을 누적 3회 이상 수행한 로그인 사용자에게 리뷰 작성을 **부드럽게 유도**한다.
"나중에"를 선택하면 서버에 유예 상태가 저장되어 유예 기간 동안 다시 나타나지 않고,
어느 기기에서 접속해도 동일하게 동작한다. 이미 리뷰를 작성한 사용자에게는 유도가
나타나지 않는다.

**Why this priority**: 리뷰 작성률을 끌어올리는 부스터이며 US2(리뷰 작성)가 먼저
존재해야 의미가 있다. 없어도 커뮤니티 기능 자체는 완결된다.

**Independent Test**: 신규 로그인 계정으로 검색 3회 수행 → 유도 노출 확인 →
"나중에" 선택 → 재접속·타기기 접속 시 유예 기간 내 미노출 확인 → 리뷰 작성 후
영구 미노출 확인.

**Acceptance Scenarios**:

1. **Given** 리뷰 미작성 로그인 사용자가 누적 검색 3회에 도달했다, **When** 검색
   결과가 표시되고 짧은 지연이 지난다(핵심 결과 확인을 가리지 않기 위함), **Then**
   리뷰 작성 유도가 1회 표시되고 "작성하기"와 "나중에" 중 선택할 수 있다.
2. **Given** 유도에서 "나중에"를 선택했다, **When** 유예 기간 내에 다시 서비스를
   사용한다(다른 기기 포함), **Then** 유도가 다시 나타나지 않는다.
3. **Given** 유예 기간이 지났고 여전히 리뷰 미작성 상태다, **When** 검색을 수행한다,
   **Then** 유도가 다시 나타날 수 있다.
4. **Given** 이미 리뷰를 작성한 사용자다, **When** 검색을 아무리 수행해도, **Then**
   유도가 나타나지 않는다.
5. **Given** 게스트 상태로 검색 3회에 도달했다, **When** 검색을 마친다, **Then**
   리뷰 유도는 나타나지 않는다(리뷰는 로그인 전용이므로 게스트에게는 소음이다).

### Edge Cases

- 공개 플레이리스트 0개·리뷰 0건일 때: 각 피드는 빈 상태 안내를 표시하고 서로
  독립적으로 동작한다(한쪽이 비어도 다른 쪽 조회 가능).
- 사용자 입력에 HTML 태그·스크립트가 포함될 때: 어떤 화면에서도 해석·실행되지 않고
  입력한 원문 그대로 텍스트로 표시된다(리뷰·댓글 공통).
- 별점 없이 제출·범위(1~5) 밖 별점·길이 상한 초과 텍스트: 저장이 거부되고 정제된
  안내 문구가 표시된다(원시 오류 노출 금지 — 기존 F4 원칙).
- 두 탭·두 기기에서 동시에 첫 리뷰를 제출할 때: 하나만 저장되고 나머지는 중복 안내를
  받는다(1인 1건이 최종적으로 보장됨).
- 피드 조회 중 대상 플레이리스트가 비공개 전환·삭제된 경우: 상세 진입·댓글 작성이
  거부되고 존재 비노출 원칙을 따른다.
- 리뷰 작성자가 닉네임을 변경한 경우: 피드에는 현재 닉네임이 표시된다.
- 커뮤니티 화면 조회는 서버 지연·오류 시에도 앱의 다른 기능(검색 등)에 영향을 주지
  않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 게스트를 포함한 모든 사용자에게 커뮤니티 화면을 제공해야
  하며, 화면 상단 **세그먼트 전환**(플레이리스트/리뷰)으로 공개 플레이리스트 피드와
  서비스 리뷰 피드를 각각 독립된 목록으로 제공한다. 조회에 로그인을 요구해서는 안 된다.
- **FR-002**: 공개 플레이리스트 피드는 공개 상태의 플레이리스트만 최신순으로 페이지
  단위 조회를 제공해야 하며, 각 항목에 이름·곡 수·대표 커버·작성자 닉네임을 포함한다.
  항목 선택 시 기존 공개 플레이리스트 상세로 연결된다.
- **FR-003**: 서비스 리뷰 피드는 별점·내용·작성자 닉네임·작성일을 최신순으로 페이지
  단위 조회를 제공해야 한다.
- **FR-004**: 로그인 사용자는 별점(1~5 정수, 필수)과 텍스트 내용으로 서비스 리뷰를
  작성할 수 있어야 한다. 리뷰는 **사용자당 1건**으로 제한되며, 이미 존재하는 상태의
  중복 작성 요청은 저장 없이 거부되고 사용자에게 기존 리뷰 수정 경로가 안내되어야 한다.
- **FR-005**: 리뷰의 수정·삭제는 작성자 본인만 가능해야 한다. 삭제 후에는 새 리뷰
  작성이 다시 가능하다. 타인 리뷰에 대한 변경 시도는 권한 없음으로 거부한다(리뷰는
  피드에 공개된 자원이므로 존재 비노출 위장은 불필요 — 비공개 자원과 구분).
- **FR-006**: 로그인 사용자는 공개 플레이리스트에 댓글을 작성할 수 있어야 하고, 댓글
  목록은 게스트를 포함해 누구나 조회할 수 있어야 한다. 삭제는 작성자 본인만 가능하다.
  공개 상태가 아닌 플레이리스트에는 댓글을 작성할 수 없다.
- **FR-007**: 리뷰·댓글 등 모든 사용자 입력 텍스트는 플레인 텍스트로 저장·표시되어야
  한다. 어떤 화면에서도 입력 텍스트를 마크업으로 해석·실행해서는 안 된다(v2 XSS 제거
  확정 사항 계승).
- **FR-008**: 게스트가 작성 계열 동작(리뷰 작성·댓글 작성)을 시도하면 기존 패턴대로
  로그인 유도를 표시하고, 로그인 완료 후 원래 맥락으로 복귀시켜야 한다.
- **FR-009**: 리뷰 내용은 최대 **500자**, 댓글은 최대 **300자**로 제한하며, 검증
  실패 시 표준 오류 응답과 정제된 안내 문구로 처리한다(원시 오류 메시지 직접 노출 금지).
- **FR-010**: 시스템은 리뷰 미작성 로그인 사용자가 누적 검색 3회에 도달하면 리뷰 작성
  유도를 표시해야 한다. "나중에" 선택 시 유예 만료 시각을 **서버에** 저장해 **7일**
  (운영 조정 가능한 설정값) 동안 어느 기기에서도 재노출하지 않으며, 리뷰 작성
  완료자에게는 유도를 표시하지 않는다. 게스트에게는 유도를 표시하지 않는다. 선택
  없이 닫으면(배경 탭·ESC 등) 같은 세션에서는 재노출하지 않되 유예는 저장하지 않는다.
- **FR-011**: 커뮤니티 관련 사용자 행동은 기존 이벤트 수집 체계로 계측되어야 한다 —
  최소: 커뮤니티 화면 조회, 리뷰 유도 노출, 리뷰 제출, 댓글 제출. 리뷰 작성률 등
  헬스 메트릭을 수집 데이터에서 산출할 수 있어야 한다.
- **FR-012**: 커뮤니티 진입점은 하단 내비게이션의 **5번째 탭**으로 추가한다
  (홈·즐겨찾기·기록·플레이리스트·커뮤니티). 검색 플로우 몰입 유지 원칙(검색 중 내비
  숨김)은 기존과 동일하게 적용된다.

### Key Entities

- **서비스 리뷰**: 사용자가 앱(서비스 전반)에 남기는 평가. 작성자(사용자당 1건 —
  고유 제약), 별점(1~5 정수), 내용(플레인 텍스트, 최대 500자), 작성·수정 시각.
  곡·플레이리스트와는 연결되지 않는다.
- **댓글**: 공개 플레이리스트에 달리는 짧은 글. 대상 플레이리스트, 작성자, 내용
  (플레인 텍스트, 최대 300자), 작성 시각. v1은 단일 깊이(대댓글 없음).
- **리뷰 유도 상태**: 사용자별 유예 만료 시각(서버 저장). 만료 전에는 유도를 재노출하지
  않는다. 사용자 프로필에 속하는 상태다.
- **공개 플레이리스트(기존)**: 피드 노출 대상. 이 기능을 위해 새 속성을 추가하지
  않으며 기존 공개/비공개 상태를 그대로 따른다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 게스트가 로그인 없이 앱 진입에서 두 번의 탐색 동작 이내로 커뮤니티
  피드(공개 플레이리스트·리뷰)를 조회할 수 있다.
- **SC-002**: 이미 리뷰가 있는 계정의 재작성 시도는 100% 저장이 거부되고, 매번 기존
  리뷰 수정 경로가 안내된다(동시 제출 포함 — 최종 상태는 항상 1건).
- **SC-003**: 스크립트·HTML 태그를 포함한 리뷰·댓글 입력이 실행되는 사례가 0건이며,
  입력 원문이 그대로 텍스트로 표시된다.
- **SC-004**: 리뷰 작성률(로그인 사용자 대비 리뷰 작성자 비율)과 커뮤니티 조회 규모를
  수집된 이벤트 데이터에서 산출할 수 있다(헬스 메트릭 원천 확보).
- **SC-005**: 검색 3회 누적을 충족한 리뷰 미작성 로그인 사용자에게 유도가 노출되고,
  "나중에" 선택 후 유예 기간 내 재노출이 0건이다(기기 교체 포함).
- **SC-006**: 커뮤니티 피드 첫 페이지가 일반적인 사용 환경(웜 서버 기준)에서 3초
  이내에 표시된다.

## Assumptions

- **댓글 깊이**: v1은 단일 깊이(대댓글 없음)로 한정한다. 마스터 PRD의 대댓글 여지는
  이번 범위에서 구현하지 않는다.
- **댓글 수정**: v1은 삭제만 제공하고 수정은 제공하지 않는다.
- **정렬**: 두 피드 모두 최신순 고정(v1). 검색·필터·정렬 옵션은 범위 밖이다.
- **범위 제외**: 팔로우·공유하기·신고·알림·리뷰 피드의 페이징 외 탐색 기능은 이번
  기능에 포함하지 않는다(마스터 PRD상 M5+ 또는 제안 단계).
- **기존 자산 재사용**: 공개 플레이리스트 조회 능력, 로그인 유도(GuestPrompt)·맥락
  복귀 패턴, 페이지 단위 목록 패턴, 이벤트 수집 체계(event_log)를 재사용한다. 리뷰
  노출 유예는 기존 실행 PRD에 예정된 사용자 속성(review_hide_until)을 사용한다.
- **닉네임 노출**: 피드·댓글에는 작성자의 현재 닉네임(와 아바타)을 표시한다. 익명
  옵션은 제공하지 않는다.
