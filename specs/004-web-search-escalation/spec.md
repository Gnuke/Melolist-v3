# Feature Specification: 웹검색 심층 곡 탐색 (더 깊이 찾기)

**Feature Branch**: `004-web-search-escalation`

**Created**: 2026-08-04

**Status**: Draft

**Input**: User description: "웹검색 에스컬레이션 검색 (spec 004, 방식 B). AI 자연어 폴백 검색(spec 002)이 무결과이거나 사용자가 결과에 불만족할 때, 사용자가 명시적으로 누르는 '더 깊이 찾기' 에스컬레이션 버튼으로 웹검색 기반 심층 곡 탐색을 실행한다. 진입점 2곳: AI 폴백 무결과 안내 화면 + AI 폴백 결과 불만족(원하는 곡 없음) 화면. 웹검색 발동 시 19~21.5s 실측이므로 ~30초 별도 타임아웃 예산과 진행 표시 UI 필요. 별도 일일 쿼터(예: 사용자당 2회/일, 기존 AI 폴백 쿼터와 독립) — 발동 시 회당 비용이 크므로 쿼터로 총액 캡. 핵심 쟁점: 웹검색의 주 사용 사례가 기존 카탈로그에 없는 신곡인데, 기존 메타 대조 필터를 그대로 적용하면 정답이 걸러짐 — 웹 근거 후보는 메타 대조 완화 + '미확인' 라벨 표시 등의 UX 필요. 계측: 기존 AI 검색 이벤트 체계에 준하는 에스컬레이션 이벤트(발동/결과/선택/쿼터 소진) 추가."

## Clarifications

### Session 2026-08-04

- Q: 미확인 후보에 웹검색이 함께 찾아온 재생 링크(유튜브)를 사용할 것인가? → A: 사용한다
  — 미확인 표시와 함께 링크를 표시하고, 재생·저장(채택 시 곡 데이터 합류)에도 사용한다.
- Q: 회당 비용이 큰 심층 탐색을 게스트에게도 허용하는가? → A: 로그인 사용자 전용.
  게스트가 진입점을 누르면 기존 패턴대로 로그인 유도 후 원래 맥락으로 복귀한다(기본
  검색·AI 폴백의 게스트 접근은 기존대로 유지).
- Q: 진입점 선택 시 즉시 실행하는가, 확인 단계를 거치는가? → A: 확인 단계 경유 —
  기존 질의를 미리 채워 수정 기회를 주고, 예상 소요 시간과 남은 횟수를 고지한 뒤
  사용자가 실행을 확정한다. 한도는 실행 확정(접수) 시점에 집계한다.
- Q: 일일 한도 수치는? → A: 로그인 사용자당 2회/일로 확정. 운영 데이터에 따라 조정
  가능한 설정값으로 둔다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - AI 검색 무결과에서 "더 깊이 찾기"로 재시도 (Priority: P1)

말로 설명해서 찾기(AI 폴백 검색)가 후보를 찾지 못했을 때, 사용자는 무결과 안내 화면에서
**"더 깊이 찾기" 버튼**을 눌러 웹의 최신 정보를 활용한 심층 탐색으로 이어갈 수 있다.
버튼을 누르면 즉시 실행되는 대신 **확인 단계**가 표시된다: 기존 질의가 미리 채워져 있어
단서를 보완할 수 있고, 오래 걸릴 수 있다는 안내와 오늘 남은 실행 횟수를 함께 확인한 뒤
실행을 확정한다. 실행 중에는 진행 상태를 표시하며, 완료되면 후보 곡 목록(최대 5곡)을
기존 검색 결과와 같은 카드 형태로 보여준다.
카탈로그 대조로 확인된 후보는 기존과 동일하게(커버·재생 링크) 표시하고, **확인하지 못한
후보도 제외하지 않고 "미확인" 표시와 함께 노출**한다 — 심층 탐색의 주 사용 사례가
카탈로그에 아직 등재되지 않은 신곡·희귀곡이기 때문이다. 심층 탐색은 로그인 사용자
전용이며, 게스트가 진입하면 로그인 유도 후 원래 맥락으로 복귀한다.

**Why this priority**: 기존 AI 폴백 검색은 모델이 기억하는 곡까지만 찾는다. 최신 발매곡·
희귀곡·모델이 모르는 곡은 무결과로 끝나며, 이 화면은 실패 경로의 마지막 막다른 길이다.
심층 탐색은 이 잔여 실패를 구제하는 유일한 수단이고, 이 스토리 하나만으로도 독립적인
가치를 전달한다.

**Independent Test**: AI 폴백 무결과 상태(또는 mock 무결과 시나리오)에서 "더 깊이 찾기"
실행 → 진행 표시 확인 → 후보 목록(확인/미확인 구분 포함) 표시 확인. 이 흐름만으로 독립
검증 가능하다.

**Acceptance Scenarios**:

1. **Given** AI 폴백 검색이 무결과 안내로 끝난 화면이다, **When** "더 깊이 찾기"를
   누른다, **Then** 기존 질의가 미리 채워진 확인 단계가 표시되고, 질의 수정이 가능하며,
   오래 걸릴 수 있다는 안내와 오늘 남은 실행 횟수가 함께 표시된다.
2. **Given** 확인 단계가 표시되어 있다, **When** 실행을 확정한다, **Then** 진행 중
   상태가 표시되고, 완료 시 후보 곡 목록(1~5곡)이 기존 검색 결과와 동일한 카드 형태로
   표시된다.
3. **Given** 심층 탐색 결과에 카탈로그 대조로 확인되지 않은 곡이 포함되어 있다,
   **When** 후보 목록이 표시된다, **Then** 해당 후보는 걸러지지 않고 "미확인" 표시와
   함께 노출되며, 확인된 후보와 시각적으로 구분된다.
4. **Given** 심층 탐색이 진행 중이다, **When** 사용자가 취소한다, **Then** 진행 중
   요청은 중단되고 이전 화면으로 복귀한다.
5. **Given** 게스트(비로그인) 상태다, **When** "더 깊이 찾기" 진입점을 누른다,
   **Then** 심층 탐색이 실행되는 대신 로그인 유도가 표시되고, 로그인 완료 후 원래의
   폴백 맥락으로 복귀한다.

---

### User Story 2 - 후보가 마음에 안 들 때 심층 탐색으로 전환 (Priority: P2)

AI 폴백 검색이 후보를 반환했지만 그중에 찾는 곡이 없을 때, 사용자는 후보 목록 화면에서
같은 "더 깊이 찾기" 진입점으로 심층 탐색을 실행할 수 있다. 원래의 AI 폴백 후보 목록으로는
언제든 돌아갈 수 있다.

**Why this priority**: 무결과(US1)보다 빈도는 낮지만, "비슷하지만 틀린 후보만 보여주고
끝"은 무결과 못지않게 신뢰를 해친다. US1의 화면·진행 표시·결과 표시를 그대로 재사용하므로
증분 비용이 작다.

**Independent Test**: AI 폴백이 후보를 반환한 화면(또는 mock 성공 시나리오)에서 "더 깊이
찾기" 진입점을 눌러 US1과 동일한 심층 탐색 흐름이 동작하는지, 원래 후보 목록으로 복귀
가능한지 확인.

**Acceptance Scenarios**:

1. **Given** AI 폴백 검색이 후보 목록을 반환한 화면이다, **When** "찾는 곡이 없나요?"
   형태의 심층 탐색 진입점을 누른다, **Then** US1과 동일한 심층 탐색이 실행된다.
2. **Given** 심층 탐색 결과가 표시되어 있다, **When** 사용자가 이전 결과로 돌아가기를
   선택한다, **Then** 원래의 AI 폴백 후보 목록이 다시 표시된다.

---

### User Story 3 - 이용 한도 확인과 소진 안내 (Priority: P3)

심층 탐색은 회당 비용이 큰 기능이므로 별도의 일일 이용 한도를 갖는다. 사용자는 확인
단계에서 오늘 남은 실행 횟수를 확인할 수 있고, 한도를 다 쓴 상태에서는 실행 대신 소진
사실과 다시 가능해지는 시점을 안내받는다. 심층 탐색 한도는 기존 AI 폴백 검색 한도와 독립이어서, 심층 탐색을 다
써도 일반 AI 폴백 검색은 계속 사용할 수 있다.

**Why this priority**: 비용 통제는 기능 존속의 전제 조건이지만, US1이 없으면 의미가 없는
보조 흐름이므로 P3. 한도 초과가 오류처럼 보이면 신뢰를 해치므로 안내 품질이 중요하다.

**Independent Test**: 한도를 소진한 사용자(또는 mock 한도 소진 시나리오)로 진입점 확인 →
실행 불가 상태와 안내(다시 가능해지는 시점 포함) 표시 확인. 이후 일반 AI 폴백 검색이
여전히 동작하는지 확인.

**Acceptance Scenarios**:

1. **Given** 오늘의 심층 탐색 한도를 모두 사용했다, **When** 진입점을 눌러 확인 단계에
   진입한다, **Then** 실행이 불가하며 소진 사실과 다시 가능해지는 시점이 안내된다.
2. **Given** 심층 탐색 한도를 모두 사용했다, **When** 일반 AI 폴백 검색을 사용한다,
   **Then** 기존 AI 폴백 한도 내에서 정상 동작한다.

---

### Edge Cases

- 심층 탐색이 제한 시간을 초과하면? → 실패로 처리하고 이해할 수 있는 안내와 함께
  재시도를 제공한다. 접수된 요청은 한도에 집계된다.
- 심층 탐색도 후보를 찾지 못하면? → 오류가 아닌 안내(보완하면 좋은 단서 예시 포함)를
  표시한다. 재시도는 가능하되 회당 한도가 소모됨을 인지할 수 있어야 한다.
- 반환된 후보가 전부 "미확인"이면? → 전멸시키지 않고 전부 미확인 표시로 노출한다.
  (기존 AI 폴백의 대조 실패 후보 제외 정책은 심층 탐색 결과에 그대로 적용하지 않는다.)
- 검색 도중 사용자가 취소하면? → 진행 중 요청은 중단되고 결과·검색 기록에 반영되지
  않으며, 접수 시점에 한도에 집계된다(취소 반복으로 한도를 우회하는 남용 방지 — 기존
  AI 폴백과 동일 정책).
- 외부 탐색 서비스가 장애이면? → 심층 탐색만 우아하게 실패하고, 일반 AI 폴백 검색과
  기본 검색(허밍/지문)은 영향받지 않는다.
- 미확인 후보를 선택하면? → 웹 근거 링크가 있으면 재생·저장 모두 가능하다. 링크가 전혀
  없는 후보의 저장은 기존 "재생 링크 미해석 곡" 정책을 따른다.
- 심층 탐색이 예상보다 빨리(수 초 내) 끝나면? → 정상 성공으로 동일하게 처리한다.
  한도 집계도 동일하다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: AI 폴백 검색의 무결과 안내 화면과 후보 목록 화면 두 곳에 심층 탐색
  진입점("더 깊이 찾기")을 제공해야 한다. 실행은 로그인 사용자 전용이며, 게스트가
  진입점을 누르면 기존 로그인 유도 패턴(로그인 후 원래 맥락 복귀)을 따른다.
- **FR-002**: 심층 탐색은 사용자의 명시적 실행으로만 시작되어야 한다. 시스템이 무결과
  등을 이유로 자동으로 심층 탐색을 발동해서는 안 된다(비용 통제). 진입점 선택 시 즉시
  실행하지 않고 확인 단계를 거친다: 기존 질의를 미리 채워 수정 기회를 제공하고, 오래
  걸릴 수 있다는 안내와 오늘 남은 실행 횟수를 고지한 뒤 사용자가 실행을 확정한다.
- **FR-003**: 심층 탐색은 일반 AI 폴백보다 완화된 별도 제한 시간(30초급)을 가지며, 진행
  중 상태(오래 걸릴 수 있다는 안내 포함)를 표시하고, 사용자가 언제든 취소할 수 있어야
  한다. 제한 시간 초과 시 실패로 처리하고 재시도를 안내한다.
- **FR-004**: 시스템은 실행당 후보 곡을 최대 5곡까지 반환하고, 각 후보를 기존 검색
  결과와 동일한 정보 구성(제목·아티스트·커버·재생 링크)으로 표시해야 한다.
- **FR-005**: 카탈로그 대조로 확인하지 못한 후보는 **제외하지 않고** "미확인" 표시와
  함께 노출해야 하며, 확인된 후보와 시각적으로 구분되어야 한다. 미확인 후보라도 웹
  근거로 확보한 재생 링크·커버가 있으면 함께 표시한다(링크·커버가 없으면 제목·아티스트
  만으로 표시).
- **FR-006**: 후보 선택 시 기존 검색 결과와 동일한 후속 행동(재생 링크 이동, 즐겨찾기,
  플레이리스트 담기)이 가능해야 한다. 미확인 후보의 웹 근거 재생 링크는 채택·저장 시에도
  유지된다. 링크가 전혀 없는 후보의 저장은 기존 "재생 링크 미해석 곡" 정책을 따르고,
  저장 계열의 로그인 요구 규칙도 기존과 동일하다.
- **FR-007**: 심층 탐색으로 확인(선택)한 곡은 기존 검색·AI 폴백 검색과 구분 가능한
  방식으로 검색 기록에 남아야 한다(로그인 사용자에 한함 — 기존 기록 정책과 동일).
- **FR-008**: 로그인 사용자별 심층 탐색 전용 일일 이용 한도(2회/일, 운영 조정 가능한
  설정값)를 두어야 하며, 기존 AI 폴백 한도와 독립적으로 관리되어야 한다. 요청은 접수
  시점에 집계되고, 한도 초과 시 실행 대신 소진 사실과 다시 가능해지는 시점을 안내한다.
- **FR-009**: 심층 탐색의 발동·결과(성공/무결과/실패/취소/한도 초과)·후보 채택(선택한
  후보의 순위와 확인/미확인 여부 포함)을 이벤트로 수집하고, 요청별 소요 시간을 기록해야
  한다. 이 계측은 본 기능과 같은 마일스톤 안에서 함께 출고한다.
- **FR-010**: 외부 탐색 서비스 인증 정보는 서버에만 존재해야 하며 사용자 단말에 노출되지
  않아야 한다. 심층 탐색은 텍스트만 외부로 전달하고, 녹음 오디오 원본은 이 경로에서도
  전송·저장하지 않는다.
- **FR-011**: 외부 탐색 서비스를 실제로 호출하지 않고도 심층 탐색 흐름 전체(성공·전부
  미확인·무결과·실패·지연·한도 소진 시나리오)를 검증할 수 있는 수단을 함께 제공해야
  한다.
- **FR-012**: 외부 탐색 서비스 장애 시 심층 탐색만 실패해야 하며, 일반 AI 폴백 검색과
  기본 검색(허밍/지문)은 영향받지 않아야 한다.

### Key Entities

- **심층 탐색 질의**: 사용자가 심층 탐색을 실행한 시점의 설명 텍스트와 그 처리 결과
  (후보 수, 확인/미확인 구성, 소요 시간, 채택 여부·채택 순위, 실패/취소/한도 초과 여부).
  지표 산출과 비용 추적의 원천이 된다.
- **미확인 후보**: 웹 근거로만 식별되어 기존 카탈로그 대조를 통과하지 못한 곡 후보.
  웹 근거의 재생 링크·커버를 가질 수 있으며 채택 시 그 정보 그대로 곡 데이터로 합류한다.
  링크가 전혀 없는 경우의 합류는 기존 "재생 링크 미해석 곡" 정책을 따른다.
- **심층 탐색 이용 한도**: 로그인 사용자별 일일 실행 가능 횟수. 기존 AI 폴백 한도와
  독립적인 별도 원장이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: AI 폴백 검색이 무결과 또는 후보 미채택으로 끝난 세션 중 20% 이상이 심층
  탐색을 시도한다.
- **SC-002**: 심층 탐색 시도 중 30% 이상에서 사용자가 후보 곡을 선택한다.
- **SC-003**: 심층 탐색 요청의 95%가 30초 이내에 후보 목록 또는 무결과 안내를 표시한다.
- **SC-004**: 일일 한도를 초과한 심층 탐색 실행이 0건이다(비용 상한이 실제로 동작함을
  운영 데이터로 실증).
- **SC-005**: 심층 탐색의 시도 수·채택률·확인/미확인 후보 비중·소요 시간·실패율을 운영
  데이터에서 조회 가능한 상태로 출고한다(도입 시점부터 원천 데이터 수집).

## Assumptions

- **방식 B(명시적 버튼) 확정**: 심층 탐색은 사용자가 버튼을 눌러야만 실행된다. 무결과
  시 자동 발동하는 방식(방식 A)은 회당 비용 때문에 채택하지 않는다(2026-08-03 합의).
- **진입점은 AI 폴백 화면 한정**: 허밍/지문 검색의 실패 화면에서 바로 심층 탐색으로
  가는 경로는 이번 범위에 포함하지 않는다. 실패 경로의 1차 구제는 기존 AI 폴백이며,
  심층 탐색은 그다음 단계다.
- **일일 한도**: 로그인 사용자당 2회/일로 확정(Clarifications 참조). 운영 데이터에
  따라 조정 가능한 설정값으로 구현한다.
- **로그인 전용과 게스트 우선 원칙의 관계**: 심층 탐색은 회당 비용이 큰 부가 구제
  기능으로, 저장 계열과 같은 로그인 요구 분류에 둔다. 핵심 기능(기본 검색·결과 조회·
  AI 폴백)의 게스트 접근은 변경하지 않는다.
- **후보 상한 5곡**: 기존 AI 폴백과 동일한 상한을 유지한다.
- **대화가 아닌 검색**: 심층 탐색도 1회 실행 → 후보 반환의 검색 상호작용이다. 재시도는
  입력 수정 후 재실행으로 처리하며, 각 실행이 한도에 개별 집계된다.
- **미확인 후보의 신뢰 위임**: 미확인 후보는 시스템이 진위를 보증하지 않으며, "미확인"
  표시로 사용자 판단에 위임한다. 잘못된 후보 선택의 데이터 오염은 기존 곡 데이터 정본
  규칙(채택 시 합류) 범위에서 관리한다.
- **성능 목표의 성격**: 심층 탐색은 이미 두 번(기본 검색 → AI 폴백) 실패한 검색의 최종
  구제 경로이므로, 기존 AI 폴백의 응답 목표보다 완화된 별도 목표(SC-003, 30초)를
  적용한다.
- **외부 탐색 서비스 의존**: 웹 최신 정보를 활용하는 외부 서비스에 의존하며, 해당 서비스
  장애 시 심층 탐색만 우아하게 실패한다.
